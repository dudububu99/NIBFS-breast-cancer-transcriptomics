# Repository verification

This release includes four complementary QA layers:

1. `scripts/verify_release_metadata.py` checks v1.2.5 release metadata across README, `CITATION.cff`, `config.yaml`, `src/__init__.py`, the package marker, release notes, and release summary.
2. `scripts/verify_file_manifest.py` validates SHA-256 hashes, file sizes, duplicate/path safety, and exact coverage of all non-transient release files. Runtime caches (`__pycache__/`, `.pytest_cache/`, `*.pyc`, notebook checkpoints, editor caches) are intentionally excluded.
3. `scripts/verify_paper_archive.py` checks compact machine-readable evidence supporting the manuscript, including frozen-panel identity, fold assignments, stability values, LASSO nonzero auditing, network controls, external datasets, and TCGA-BRCA pair/panel checks.
4. `pytest -q` runs deterministic unit/smoke tests for TCGA helpers and core feature-selection/stability/model-metric utilities.

The manifest is generated by `scripts/build_file_manifest.py`. The release manifest does not include itself because a file cannot contain its own stable cryptographic hash.

Pre-publication GitHub packaging QA on 2026-09-03 removed transient Python/pytest caches and harmonized release metadata. No scientific output, prediction, selected panel, fold assignment, or analysis result was changed by this packaging step.

## Reviewer-first entry point

Reviewers and supervisors can run all non-rerun verification layers with:

```bash
python scripts/verify_repository.py --with-tests
```

See `START_HERE_REVIEWERS.md` for local Windows/macOS/Linux instructions and the distinction between verification of archived evidence and optional end-to-end reproduction.
